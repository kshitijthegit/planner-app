# Notes for Claude

- Owner: KJ (single user), primary planner. Theme: Phthalo & Coffee, with a phthalo green background, latte accent, paper Top 3 cards, and Playfair Display + Inter Tight. Tokens are in `src/styles.css`.
- Subtasks: max 2 levels, enforced in `worker/modules/tasks.ts`; each subtask has its own deadline.
- Linked calendars live at `/calendars` (per-calendar sync switches). Google sync uses `config.calendarIds`, where `[]` means everything is off.
- Project rule: don't edit the codebase unless KJ explicitly asks.
- Areas: Personal (espresso), University (mocha), Work (latte). Filters are by area (`area_id`, falling back to the category's area). Calendar colours (`itemColor` / `PALETTE` in `src/lib/items.ts`): goals brass, tasks terracotta (any area), done tasks sage, birthdays/anniversaries dusty rose (Google `event_type` birthday or title match), synced events slate blue; only own events use their area colour.
- Items: events are filled blocks, tasks are thin blocks with a check, and goals are unfilled blocks at the top of the day. Untimed items go to the top of the day, and an all-day event makes the whole day white.
- New items go through `AddFlow` (area first, then details). Dropdowns use `CreatableSelect`, so each can add a new option.
- Calendar grid shows 24 hours with no scrolling; positions are percentages of the column height.
- The background follows the time of day (`src/lib/daytheme.ts` sets CSS variables hourly and adds `.theme-light` on light shades). Never hard-code text or surface colours; use the variables.
- Events: attendance (yes/maybe/no → normal/dashed/faint) and recurrence, which is expanded server-side; an occurrence edits the whole series.
- Undo: every store mutation pushes an inverse operation (`pushUndo`), triggered by Ctrl/⌘+Z or the toast button. POST accepts `id` so deleted rows can be restored.
- Calendar tasks: day and week views show all tasks, with subtasks labelled "Sub-subtask → Subtask → Main" and staggered under any parent on the same day (`stagger()`). Month view lists no tasks, only "N tasks due" per day.
- Repeating events and goals: changes to a single occurrence go in `occurrence_overrides` (cancel, done_at, or a data patch). Editors show an "Only this one / Every occurrence" switch.
- Calendar sources come in four kinds: google (with calendarIds + eventTypes), ics, holiday (Google public ICS feeds, which never whiten the day) and file (uploaded .ics stored in `source_files`).
- Gmail add-on lives in `gmail-addon/` (Apps Script; `Parse.gs` is plain JS tested by `src/lib/gmailParse.test.ts`). It talks to `worker/modules/capture.ts` using a Bearer access key, which can reach only `/api/capture` and `/api/capture/meta`. If the app's URL changes, update `urlFetchWhitelist` in its manifest.
- Date and time entry uses `pickers.tsx` (DateField / TimeField / DateTimeField), never native date inputs.
- GUI: Today page = home (Top 3, timeline, quick add, shutdown card). Calendar = day/week/month with a drag-to-time-block task tray.
- Areas → Categories (2 levels) colour every task and event. Synced events get a category per source, overridable per series.
- Calendar sync is read-only (Google + ICS). Work Outlook is out of scope for now.
- Keep everything modular: see README "Modules". Append DB migrations; never edit old ones.
- Never commit secrets. `GOOGLE_CLIENT_SECRET` and `ALLOWED_EMAIL` are Cloudflare secrets. ICS URLs live only in D1, and the API masks them.
- Before pushing: `npm run typecheck && npm test && npm run build`.
- AI layer is planned for v2.
